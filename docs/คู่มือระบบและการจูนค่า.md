# คู่มือระบบช่วยเหลือผู้พิการทางสายตา (Blind Assist) — ฉบับเข้าใจทั้งระบบ + จูนค่าได้

> เอกสารนี้เขียนสำหรับ "คนที่เพิ่งมารับโปรเจกต์ต่อ" — อ่านจบแล้วต้องเข้าใจว่า
> ระบบทำงานยังไง ข้อมูลไหลจากกล้องไปเป็นเสียงพูดได้ยังไง และถ้าอยาก **ปรับ
> พฤติกรรม** (เตือนไวขึ้น/ช้าลง, ระยะเตือน, ความแม่นธนบัตร ฯลฯ) ต้องไปแก้ที่ไฟล์ไหน บรรทัดไหน
>
> ไม่ต้องรู้ลึกระดับโค้ดทุกบรรทัด แต่ต้องเห็นภาพรวมและรู้ "ปุ่มปรับ" ทั้งหมด

---

## 1. ระบบนี้ทำอะไร (ภาพรวม 1 นาที)

อุปกรณ์คือ **Raspberry Pi + กล้อง OAK-D Lite** ที่ผู้พิการทางสายตาพกติดตัว ระบบช่วย 3 อย่าง:

| โหมด | ชื่อในโค้ด | ทำอะไร |
|---|---|---|
| 🚶 **เดิน** (ค่าเริ่มต้นตอนเปิดเครื่อง) | `WALK` (=0) | เตือนสิ่งกีดขวางข้างหน้าว่าอยู่ **ซ้าย/กลาง/ขวา** และใกล้แค่ไหน + นำทางตาม **ทางเดินคนตาบอด (กระเบื้องสีเหลือง)** |
| 💵 **เงิน** | `MONEY` (=1) | ส่องธนบัตรไทยแล้วบอกว่าเป็นใบละเท่าไหร่ (20/50/100/500/1000) |
| 👤 **ใบหน้า** | `FACE` (=2) | จำหน้าเพื่อนที่เทรนไว้ แล้วพูดชื่อออกมา |

ผู้ใช้ **สั่งสลับโหมดด้วยเสียง** และระบบ **พูดตอบกลับเป็นเสียง** (ไทยหรืออังกฤษ) เพราะผู้ใช้มองไม่เห็น
นอกจากนี้มี **หน้าเว็บ** (`http://<ip>:8080`) ให้คนช่วยเหลือ/ผู้พัฒนาเปิดดูภาพสดและข้อความเตือนได้

**หลักการสำคัญ:** OAK-D Lite มีกล้องตัวเดียว จึงรันได้ **ทีละโหมด** การสลับโหมดคือการปิดไปป์ไลน์เดิมแล้วสร้างใหม่ (ใช้เวลา ~1–2 วินาที)

## 2. สถาปัตยกรรม — ระบบประกอบด้วย 4 "node"

ระบบนี้สร้างบน **ROS 2** (Robot Operating System) แต่ละส่วนเรียกว่า **node** คุยกันผ่าน **topic** (เหมือนช่องส่งข้อความ) แบ่งงานกันชัดเจน:

```
                ┌─────────────────────────────────────────────────────────┐
                │                  กล้อง OAK-D Lite                        │
                └───────────────────────────┬─────────────────────────────┘
                                             │ ภาพ + depth
                                             ▼
   เสียงผู้ใช้พูด           ┌──────────────────────────────┐
   "เช็คธนบัตร" ──────────► │  speech_logger_node          │  ฟังไมค์ → แปลงเป็นคำสั่ง
                            │  (หู ของระบบ)                 │
                            └──────────────┬───────────────┘
                                           │ /oak/mode_cmd (สลับโหมด)
                                           ▼
                            ┌──────────────────────────────┐
                            │  main_pipeline_node          │  สมองตา: คุมกล้อง+AI
                            │  (ตา + สมองประมวลผลภาพ)       │  ตรวจจับ แล้วส่งผลออกมา
                            └──────────────┬───────────────┘
            /money/detections /navigation/detections /face/detections /tactile/path
            /oak/current_mode  /oak/preview/compressed (ภาพ JPEG)
                                           │
                       ┌───────────────────┴────────────────────┐
                       ▼                                         ▼
        ┌──────────────────────────────┐         ┌──────────────────────────────┐
        │  decision_audio_node         │         │  web_display_node            │
        │  (ปาก: ตัดสินใจ + พูด)        │         │  (จอ: หน้าเว็บ 8080)         │
        └──────────────────────────────┘         └──────────────────────────────┘
                       │ เสียงพูดออกลำโพง
                       │ /oak/announcement (ข้อความที่พูด → ส่งให้หน้าเว็บโชว์)
                       ▼
                   🔊 ลำโพง
```

### หน้าที่แต่ละ node (จำแค่นี้ก็พอ)

1. **`main_pipeline_node`** (แพ็กเกจ `oak_detectors`) = **ตา + สมองประมวลผลภาพ**
   คุมกล้อง OAK ทั้งหมด รันไปป์ไลน์ของโหมดที่กำลังใช้ ตรวจจับ แล้วส่ง "ผลตรวจจับดิบ" ออกเป็น topic
   *ไม่พูด ไม่ตัดสินใจ* แค่ "เห็นอะไรก็รายงาน"

2. **`decision_audio_node`** (แพ็กเกจ `oak_decision_audio`) = **ปาก + สมองตัดสินใจ**
   รับผลตรวจจับดิบมา **กรอง/ยืนยัน** (เช่น ธนบัตรต้องเห็นซ้ำ 10 เฟรมถึงจะพูด, ไม่พูดซ้ำเร็วเกินไป) แล้วสั่งพูดเป็นเสียง
   **node เดียวที่พูดได้** (กันเสียงพูดทับกัน)

3. **`speech_logger_node`** (แพ็กเกจ `oak_decision_audio`) = **หู**
   ฟังไมโครโฟน แปลงเสียงเป็นข้อความ ถ้าตรงกับคำสั่ง → ส่งคำสั่งสลับโหมด *ไม่พูดตอบเอง* (ปล่อยให้ decision_audio พูด)

4. **`web_display_node`** (แพ็กเกจ `oak_decision_audio`) = **จอ**
   เปิดเว็บเซิร์ฟเวอร์ที่พอร์ต 8080 โชว์ภาพสด + โหมดปัจจุบัน + ข้อความเตือนล่าสุด ไม่มีหน้าต่าง GUI บนเครื่อง

### ตาราง topic (เส้นทางข้อมูล)

| Topic | ชนิดข้อมูล | ใครส่ง | ใครรับ | ความหมาย |
|---|---|---|---|---|
| `/oak/mode_cmd` | `Mode` | speech_logger | main_pipeline | "สลับไปโหมด X" |
| `/oak/current_mode` | `Mode` | main_pipeline | decision_audio, web_display | "ตอนนี้อยู่โหมด X แล้ว" |
| `/money/detections` | `Detection2DArray` | main_pipeline | decision_audio | ธนบัตรที่เห็น |
| `/navigation/detections` | `Detection2DArray` | main_pipeline | decision_audio | สิ่งกีดขวาง ซ้าย/กลาง/ขวา |
| `/face/detections` | `Detection2DArray` | main_pipeline | decision_audio | ใบหน้าที่เห็น |
| `/tactile/path` | `Detection2DArray` | main_pipeline | decision_audio | ทิศของทางเดินคนตาบอด |
| `/oak/announcement` | `String` | decision_audio | web_display | ข้อความที่กำลังพูด |
| `/oak/preview/compressed` | `CompressedImage` (JPEG) | main_pipeline | web_display | ภาพสดสำหรับหน้าเว็บ |
| `/oak/language` | `String` ("th"/"en") | (สั่งมือ) | ทั้ง 2 node เสียง | สลับภาษา (ปกติตั้งตอน launch) |

> 💡 อยากดูข้อมูลไหลจริงตอนระบบรัน ใช้ `ros2 topic echo <ชื่อ topic>` เช่น
> `ros2 topic echo /navigation/detections` จะเห็นว่าเตือนซ้าย/กลาง/ขวาตอนไหน

## 3. แต่ละโหมดทำงานยังไง (เข้าใจกลไก)

### 🚶 โหมดเดิน (WALK) — ทำ 2 อย่างพร้อมกัน

**(ก) เตือนสิ่งกีดขวาง — ใช้ "ความลึก (depth)" ล้วน ไม่ใช้ AI**
- กล้อง 2 ตัวของ OAK ทำงานเป็น **stereo** วัดระยะห่าง (depth) ของทุกจุดในภาพ
- เหตุที่ไม่ใช้ AI: AI ตรวจจับได้แค่ของที่เคยเทรน (คน รถ ฯลฯ) จะ **มองไม่เห็นกำแพง เสา กระจก กล่อง** ส่วน depth จับได้ **ทุกอย่างที่เป็นก้อน** เลยปลอดภัยกว่าสำหรับคนเดิน
- วิธีคิด: ตัดขอบบน/ล่างของภาพทิ้ง (กันเพดาน/พื้น) แล้วแบ่งภาพที่เหลือเป็น **3 แนวตั้ง: ซ้าย / กลาง / ขวา**
- ช่องไหนมี "พิกเซลที่อยู่ใกล้กว่าระยะเตือน" **มากพอ** → เตือนทิศนั้น พร้อมบอกระยะ

  > กติกาเตือน (ต่อ 1 ช่อง): `สัดส่วนพิกเซลใกล้ ≥ เกณฑ์` **และ** `ระยะ ≤ ระยะเตือนสูงสุด`

**(ข) นำทางตามทางเดินคนตาบอด (tactile paving)**
- จากภาพสี RGB หา **แถบสีเหลือง** (กระเบื้องนำทาง) ว่าอยู่ตรงไหนของภาพ
- ถ้าเบนซ้าย → บอก "เลี้ยวซ้าย", เบนขวา → "เลี้ยวขวา", อยู่กลาง → "ตรงไป", หาไม่เจอ/ทางตัน → "หยุด ตัดสินใจ"
- ถ้ามีสิ่งกีดขวางใกล้ การเตือนสิ่งกีดขวาง **มาก่อน** และจะปิดเสียงนำทางชั่วคราว (กันขาคนที่ยืนใกล้ถูกอ่านเป็นทางเดิน)

### 💵 โหมดเงิน (MONEY) — ใช้ AI ตรวจจับวัตถุ
- ใช้โมเดล **NN Archive** (`models/money/best.rvc2.tar.xz`, เทรนแบบ YOLO11) รันบนชิปกล้อง
- โมเดลรู้จัก 5 คลาส: `20, 50, 100, 500, 1000`
- ผลที่ได้ถูกกรองด้วย **เกณฑ์ความมั่นใจรายคลาส** (`confidence_thresholds`)
- กล้องหมุน 180° (เพราะติดตั้งกลับหัว) — ดูค่า `rotate_preview_180`
- เพื่อกัน "พูดมั่ว" ฝั่ง decision_audio จะรอให้เห็นใบเดิม **ติดกัน 10 เฟรม** ถึงจะพูด

### 👤 โหมดใบหน้า (FACE) — โครงเดียวกับโหมดเงิน
- ใช้โมเดล `models/myfriend_face/best.rvc2.tar.xz` คลาสคือ **ชื่อเพื่อน** (เช่น `Tee`, `Ping`)
- เจอใครก็พูดชื่อคนนั้นตรง ๆ ไม่เจอใครก็เงียบ และ **ไม่ประกาศตอนสลับเข้าโหมดนี้** (เงียบโดยตั้งใจ)
- ชื่อเดิมจะไม่พูดซ้ำภายใน `face_repeat_sec` วินาที

## 4. การสั่งงาน

### เลือกภาษา (ตั้งตอนเปิดระบบ)
```bash
ros2 launch oak_bringup blind_assist_system.launch.py              # ไทย (ค่าเริ่มต้น)
ros2 launch oak_bringup blind_assist_system.launch.py language:=en  # อังกฤษ
```
ระบบพูด **ทีละภาษา** ไม่พูดสองภาษาพร้อมกัน

### คำสั่งเสียง (พูดด้วยภาษาที่กำลังใช้อยู่)
| พูดว่า | ผล |
|---|---|
| "เดินต่อไป" / "walk" | → โหมดเดิน |
| "เช็คธนบัตร" / "money mode" | → โหมดเงิน |
| "สวัสดี" / "hello" | → โหมดใบหน้า |

### สั่งสลับโหมดด้วยมือ (ตอนทดสอบ ไม่ต้องพูด)
```bash
ros2 topic pub --once /oak/mode_cmd oak_interfaces/Mode "mode: 1"   # 0=เดิน 1=เงิน 2=ใบหน้า
```

### ดูหน้าเว็บ
เปิดเบราว์เซอร์ไปที่ `http://<ip-ของ-pi>:8080` จะเห็นภาพสด + โหมด + ข้อความเตือนล่าสุด

## 5. วิธี build และ run (ลำดับสำคัญมาก)

```bash
cd ~/blind_assist_ws
source /opt/ros/jazzy/setup.bash     # 1. ROS ก่อน
source venv/bin/activate             # 2. ตามด้วย venv (Python)
colcon build --symlink-install       # 3. build
source install/setup.bash            # 4. ⚠️ ต้อง source อันนี้ ไม่งั้น launch ไม่เจอ node
ros2 launch oak_bringup blind_assist_system.launch.py
```

> ⚠️ **3 กับดักที่เจอบ่อย**
> 1. ลำดับ source ต้อง **ROS ก่อน แล้วค่อย venv** เช็คด้วย `which python3` ต้องชี้ไปที่ `venv/...` ไม่ใช่ `/usr/bin/python3`
> 2. ลืม `source install/setup.bash` → error `No module named 'oak_detectors'`
> 3. เสียงพูด (TTS `edge-playback`) **ต้องต่อเน็ต** ถ้าออฟไลน์จะไม่พูด

## 6. ⭐ จุดจูนพารามิเตอร์ทั้งหมด (ส่วนที่สำคัญที่สุด)

มีไฟล์ตั้งค่า (config) **2 ไฟล์หลัก** แก้แล้ว **ต้อง `colcon build` + เปิดระบบใหม่** ค่าถึงจะมีผล
(เพราะ `--symlink-install` บางที YAML ก็ไม่ลิงก์ ถ้าไม่แน่ใจให้ build ใหม่เสมอ)

```
src/oak_detectors/config/main_pipeline.yaml          ← การมองเห็น/ตรวจจับ (กล้อง, AI, depth, ทางเดิน)
src/oak_decision_audio/config/oak_decision_audio.yaml ← การพูด/ฟัง/เว็บ (เสียง, ยืนยันผล, ไมค์)
```

> วิธีอ่านตาราง: คอลัมน์ **"ปรับเมื่อไหร่"** คือหัวใจ — บอกว่าเจออาการแบบไหนให้ขยับค่านี้ทางไหน

### 6.1 ไฟล์ `main_pipeline.yaml` (node: `main_pipeline_node`)

**กลุ่มกล้อง / ทั่วไป**

| พารามิเตอร์ | ค่าปัจจุบัน | ความหมาย | ปรับเมื่อไหร่ |
|---|---|---|---|
| `default_mode` | `walk` | โหมดตอนเปิดเครื่อง | อยากให้บูตเข้าโหมดอื่น เปลี่ยนเป็น `money`/`face` |
| `camera_fps` | `30.0` | เฟรมต่อวินาทีของกล้อง | เครื่องร้อน/หน่วง ลดลง (เช่น 15) เพื่อประหยัด CPU |
| `rotate_preview_180` | `true` | หมุนภาพ 180° (กล้องติดกลับหัว) | ถ้าภาพในเว็บกลับหัว สลับค่า |
| `nn_input_size` | `416` | ขนาดภาพเข้าโมเดล AI | ปกติไม่ต้องแตะ (ต้องตรงกับตอนเทรนโมเดล) |

**กลุ่มโหมดเงิน (MONEY)**

| พารามิเตอร์ | ค่าปัจจุบัน | ความหมาย | ปรับเมื่อไหร่ |
|---|---|---|---|
| `money_labels` | `["20","50","100","500","1000"]` | ชื่อคลาส (เรียงตามที่โมเดลออกมา) | เปลี่ยนเฉพาะเมื่อเทรนโมเดลใหม่ที่ลำดับคลาสต่างไป |
| `confidence_threshold` | `0.20` | เกณฑ์มั่นใจ "ตัวสำรอง" | ใช้เมื่อค่ารายคลาสเป็น -1 |
| `confidence_thresholds` | `[0.20,0.20,0.40,0.20,0.20]` | เกณฑ์มั่นใจ **รายใบ** (20,50,100,500,1000) | ใบไหน **มั่วบ่อย → เพิ่มค่าของใบนั้น**; ใบไหน **ไม่ค่อยจับได้ → ลดค่า**. ค่า -1 = ใช้ตัวสำรองด้านบน |
| `money_model_path` | (auto) | path ไฟล์โมเดลเงิน | เปลี่ยนเมื่อเอาโมเดลใหม่มาวางคนละที่ |

**กลุ่มโหมดใบหน้า (FACE)**

| พารามิเตอร์ | ค่าปัจจุบัน | ความหมาย | ปรับเมื่อไหร่ |
|---|---|---|---|
| `face_labels` | `["Tee","Ping"]` | ชื่อคนที่โมเดลรู้จัก | เปลี่ยนตามโมเดลที่เทรน |
| `face_confidence_threshold` | `0.7` | เกณฑ์มั่นใจใบหน้า | ทักผิดคนบ่อย → เพิ่ม; ไม่ค่อยทักทั้งที่เห็น → ลด |

**กลุ่มโหมดเดิน — เตือนสิ่งกีดขวาง (depth)** ← จูนบ่อยที่สุด

| พารามิเตอร์ | ค่าปัจจุบัน | ความหมาย | ปรับเมื่อไหร่ |
|---|---|---|---|
| `walk_obstacle_z_max_mm` | `500.0` | **ระยะเตือนสูงสุด (มม.)** ใกล้กว่านี้ถึงเตือน | อยากให้เตือนไกลขึ้น เพิ่มค่า (เช่น 1000–1500 = 1–1.5 ม.); อยากเตือนเฉพาะใกล้มาก ลดค่า |
| `walk_obstacle_min_pixel_frac` | `0.04` | สัดส่วนพิกเซลใกล้ขั้นต่ำ (0.04 = 4%) ที่ต้องมีในช่อง ถึงนับเป็นสิ่งกีดขวาง | **เตือนหลอนบ่อย (จับจุดเล็ก ๆ) → เพิ่ม**; ของเล็ก/บางตรวจไม่เจอ → ลด |
| `walk_roi_top_frac` | `0.1` | ตัดขอบ **บน** ของภาพทิ้งกี่ % (กันเพดาน) | เพดาน/ของสูงถูกเตือนผิด → เพิ่ม |
| `walk_roi_bottom_frac` | `0.9` | เก็บภาพถึงแถวล่างที่กี่ % (ส่วนล่างกว่านี้ = พื้น ตัดทิ้ง) | **พื้นถูกเตือนเป็นสิ่งกีดขวาง → ลดค่า** (เช่น 0.8) |
| `walk_manual_focus` | `15` | ล็อกโฟกัสเลนส์ (0=ไกล, 255=มาโคร) กันเลนส์ไล่โฟกัสไปมา | ภาพเบลอ/เลนส์หาโฟกัสตลอด → ปรับเลขนี้จนภาพชัดที่ระยะเดิน |

### 6.2 ไฟล์ `oak_decision_audio.yaml`

ไฟล์นี้มี **3 node** อยู่รวมกัน (`decision_audio_node`, `web_display_node`, `speech_logger_node`)

**`decision_audio_node` — การพูดและการยืนยันผล**

## 9. คำศัพท์ที่ควรรู้

- **ROS 2 / node / topic** — เฟรมเวิร์กหุ่นยนต์; node = โปรแกรมย่อย; topic = ช่องส่งข้อความระหว่าง node
- **OAK-D Lite** — กล้องอัจฉริยะที่มีชิปรัน AI ในตัว + กล้องคู่วัดระยะ (depth) ได้
- **depth / stereo** — การวัดระยะห่างของวัตถุจากภาพกล้องสองตา
- **NN Archive (.tar.xz)** — รูปแบบไฟล์โมเดล AI ที่ OAK ใช้ (รุ่นใหม่กว่า `.blob`)
- **confidence threshold** — เกณฑ์ความมั่นใจ ต่ำกว่านี้ทิ้งผลตรวจจับนั้น
- **tactile paving** — กระเบื้องนำทางผู้พิการทางสายตา (แถบสีเหลืองมีปุ่ม)
- **TTS** — Text-To-Speech แปลงข้อความเป็นเสียงพูด
